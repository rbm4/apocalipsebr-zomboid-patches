Date: 2026-10-27. Target: the supplied 42.22.0 pre-release vanilla sources.
Status: comparison complete; patch implementation, target-JAR compilation and
runtime validation remain pending. See the [target documentation index](../README.md).

Later checkpoint on the same date: the user authorized copying the 50

## Scope and evidence

Every Java file under `42.21.0/src/zombie/` is included: **301 source files**, made
up of **101 vanilla replacement files and 200 support files absent from both
vanilla baselines**. Nested/anonymous classes are covered by their containing
source file, not counted as separate Java files. The separate `42.21.0-client`
target is outside this server-tree audit; client diagnostic classes inside the
unsuffixed server source tree are included.

For each replacement, compare the old vanilla file with both the old patch and
the new vanilla file. SHA-256 establishes exact baseline equality. For changed
baselines, `git merge-file --stdout --diff3` uses old patched source as ours,
old vanilla as base and new vanilla as theirs, with line endings normalized to
LF. Merge output is discarded; nothing is copied into `src` or deployed.

files are byte-identical, 486 changed, 31 were added and 18 removed. The inventory
records every added/removed/changed vanilla path. This broader delta matters:
an unchanged patched class can call a changed class outside the patch inventory.

"Carry-over candidate" means no same-file upstream change was found. It does not
mean binary compatibility or gameplay correctness has been proved. Follow the
repository's target-baseline workflow even for these candidates. Likewise, a
clean merge is only textual evidence; it is not permission to ship an old class.

## Changes that determine the migration order

### Collection signatures and object membership

`zombie/util/list/PZArrayList.java` is missing from the new source tree.
`IsoGridSquare.getObjects()` now returns `List<IsoObject>` instead of
`PZArrayList<IsoObject>`. Context/container APIs on `IsoGameCharacter`,
`IsoGridSquare`, `IsoObject`, `BaseVehicle` and `VehicleParts` also use `List`.
These are JVM descriptor changes, including return types: keeping the old
signatures can fail calls from unpatched 42.22.0 classes even if local patches
compile together. Preserving an old `PZArrayList` implementation does not repair
those contracts.

Rework the `apocbrReadOnlyElements()`/raw-array mutation and reconciliation
optimization around the target collection contract. The conflicting consumers
include `IsoGridSquare`, `IsoChunk`, `IsoGenerator`, `LootRespawn` and
`LoadGridsquarePerformanceWorkaround`. Preserve registry ordering, removal,
mutation notifications and pooled-object lifecycle. Also recheck `IsoMannequin`,
whose vanilla collection loop changed despite a clean merge.

### Combat, player fields and trading

Old `WeaponHit`, `Damage`, `PlayerHitCharacter`, `AnimalHit`, `ZombieHit` and
`AntiCheatHitDamage` files are absent. New combat code uses `Hit`,
`CombatManager.TargetHitList` and changed `PlayerHit` contracts. `PlayerHitPlayerPacket`
changes superclass, packet handling and attack/reaction methods;
`PlayerHitSquarePacket` changes `set` to accept a `TargetHitList` despite merging
cleanly. Rebuild NPC combat against the new processing and wire contract and
preserve exactly-once damage/ammo behavior. Do not carry the old `WeaponHit`
replacement forward as a substitute for the new protocol.

`PlayerID` is now final with private fields. `PlayerDamagePacket`,
`PlayerEffectsPacket` and `PlayerStatsPacket` stop inheriting it and compose a
`ConnectionPlayer`; `SyncPlayerStatsPacket` uses `OnlinePlayer`. Port ownership
guards around those target fields rather than retaining obsolete inheritance.
Review packet registrations/handling in target `PacketTypes` and related classes.

`Trading` is absent. Trading packets now extend `PlayerRequestPacket`, whose
sender is `ConnectionPlayer` and destination is `OnlinePlayer`.
`RequestTradingPacket` no longer contains Ask/Accept/Reject or `accept`/`reject`
methods; separate `AcceptTradingPacket` and `RejectTradingPacket` classes and
`TradingRequests` handle that flow. Move NPC destination resolution/interception
to the new contract and review the new accept/reject paths as possible additional
patch points. Preserve sender ownership, distance/consent checks, session
cancellation and persistence-before-credit guarantees.

### Zombie serialization and upstream fixes

`ZombiePacket` changes `grappledBy` from `PlayerID` to `OnlinePlayer`, reports
56 rather than 53 packet-size bytes, and removes `write(ByteBuffer)` in favor
of `write(ByteBufferWriter)`. **`NetworkZombiePacker` has a byte-identical vanilla
baseline but its patched snapshot path still calls `write(this.snapshotBuffer)`
with a raw `ByteBuffer`.** Adapt that call when porting the target packet, and
compare frozen bytes with the new serializer, including optional grapple data.
The async sender owns frozen bytes and should be reviewed as a separate component.

`NetworkZombieAI` adds a server fallback when animator state is null; reconcile
it with our split bookkeeping/field-preparation methods. The scheduler adds
per-player `numChasingZombies` reset/counting; preserve this in the indexed path.
`ZombieCountOptimiser` uses the new `IsoPlayer.anyPlayerMP` helper.

### Persistence, character reconstruction and world format

`IsoWorld.WorldVersion` moves from **249 to 251**, with named vehicle milestones
250 (towed-by ID) and 251 (attempted key drop). Keep the new item/chunk/vehicle
read/write logic, version guards and network loader versions. Avoid globally
replacing historical 249 values: old datasets still require their actual format.

`ApocBRWorldDictionaryDatabase` has SQL insert/filter literals for
`game_build='42.21.0'` and `world_version=249`. `ApocBRPlayerRelationalDatabase`
records `42.21.0` in new dataset metadata. Both need explicit target-build policy,
while preserving old provenance and namespace isolation. Review schema/namespace
bootstrap and the existing dictionary/persistence guides before migration.

`IsoGameCharacter` renames protected `leftHandItem`/`rightHandItem` to
`primaryHandItem`/`secondaryHandItem`; **the relational reconstruction helper
still writes the old names through reflection**, a runtime failure compilation
alone will not catch. Recheck target save/load fields and hand/equipment replay.
`realz` also changes from byte to float; existing NPC byte casts require review
for fractional-height movement/climbing.

`InventoryItem` tightens length validation and adds `loadByteCount`;
`ItemContainer` adds cycle/depth protections and removes `removeItemOnServer`.
Preserve these changes while reapplying mutation capture. `VehiclesDB2` repairs
stored chunk coordinates, validates coordinates and uses revised vehicle save
state. Review the PostgreSQL replacement paths as well as SQLite paths; a clean
text merge does not ensure the new checks reach the custom persistence adapter.

### Entity lifecycle, world loading and security behavior

`GameEntity.isAddedToEngine()` becomes `isAddedOrScheduledForEngine()`.
`EngineEntityManager` changes pending-add cancellation/removal flags;
`GameEntityManager` removes from the engine before its registration branch and
changes meta release checks. Revalidate the entity/using-player indexes as one
lifecycle, even though all three replacements merge without conflicts.

`ServerMap.ServerCell.Load2()` returns void instead of boolean; completion queue
handling/error cleanup moves into the caller. Save pausing now unwinds in a
`finally`. Reconcile our cross-tick loading, unload and shutdown barriers with
these changes instead of choosing either side of a conflict wholesale.

`ChatServer` adds chat-membership/author checks and changes whisper intake to
accept the connection. `IsoObject.syncIsoObjectReceive` also gains the source
connection, with sheet-rope damage validation; `IsoGenerator` and `IsoThumpable`
update their overrides. Preserve the new validation when restoring bridge hooks.
Door forcing and edge APIs use `isNorth()` instead of `getNorth()`.

`DesignationZoneAnimal` replaces its animal list with a set and exposes
`getAnimalsInZone()` snapshots. Its supplied `doMeta` source contains an outer
size loop around the baby-animal iteration; review this separately before
making behavior-preservation claims. Do not silently treat it as an intended
optimization or fix it as part of an unrelated port.

## Implementation sequence and verification remaining

1. Establish the new collection/entity/world-format contracts and retire obsolete
   replacement targets; retain target signatures in every replacement.
2. Rebase shared engine, character, inventory, streaming and persistence patches.
3. Port packet ownership, zombie snapshot serialization, combat and trading as
   coordinated changes with the new packet classes and registries.
4. Bring over support classes and migrate the owning feature guides as each
   implementation is verified. Keep 42.21.0 reports and measurements historical.
5. Compile using the 42.22.0 patch script and an exact 42.22.0 game JAR with
   `-DryRun`. Existing `tools/test_*.py` fixtures target 42.21.0 explicitly; adapt
   relevant fixtures before claiming they validate the new build. Validate
   packet bytes/ownership, collection mutation and unload/reuse, entity pending
   operations, dataset provenance and hand/equipment round trips.
6. Test NPC synchronous/asynchronous modes, shutdown, reconnect, combat, trades,
   streaming and native/Lua integration on an isolated 42.22.0 runtime.

This task performed source comparison and documentation validation only. No
Java source was ported, no Java fixture or target-JAR build was run, and no live
server/client or database was modified. The existing version scripts and library
folder do not establish that the target is ready to deploy.
